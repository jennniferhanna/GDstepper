# GDstepper: Object-Oriented Gradient Descent using Rcpp

## 1. Remote Installation Instructions
To install this package directly from GitHub, please run the following command in your R console:

```R
# install.packages("devtools")
devtools::install_github("jennniferhanna/GDstepper")
```

## 2. Verification of Rcpp and OO Structure
To verify that the C++ algorithm successfully runs and returns an Object-Oriented S3 class, run the 
following example. This will generate data, fit a linear regression using the C++ gradient descent 
function, and utilize the custom `print.gradr_fit` method.

```R
library(GDstepper)

# Generate dummy data for y = 2x + 1
x <- 1:10
y <- 2 * x + 1

# Fit the model using the R wrapper for the Rcpp function
model <- fit_gd(x, y, alpha = 0.01, iterations = 2500)

# Print the custom OO object
print(model)
```

## 3. Unit Test Report
The package utilizes the `testthat` framework for unit testing. When running `devtools::test()`, 
the suite reports **0 Fails and 4 Passes**. 

I chose to test three specific areas to ensure the package functions correctly and safely:

*   **Object-Oriented Integrity (How: `expect_s3_class`)**: I tested the R wrapper function `fit_gd()` 
to ensure it correctly assigns the custom `gradr_fit` class to the output list generated by the C++ code. 
This ensures the custom print method will always trigger.
*   **Algorithmic Accuracy (How: `expect_equal`)**: I passed dummy data with a known slope and intercept 
(y = 2x + 1) into the model. Because gradient descent is an approximation, I used `expect_equal` with a `tolerance` 
argument to verify that the C++ math converges precisely on the expected coefficients.
*   **Edge Cases & Error Handling (How: `expect_error`)**: I tested how the R wrapper handles bad data *before* 
passing it to C++. By submitting an `x` vector and `y` vector of unequal lengths, I used `expect_error` to verify 
that the R function safely catches the mismatch and stops execution, preventing a C++ crash.
